# Just One KISS - Still Image Marketing Inventory of Possibilities

**Purpose:** Generic inventory of possible still-image marketing materials that can be produced for Just One KISS across social, paid, website, print, venue, booking, fan, and owner/admin contexts.

**Status:** Inventory-only planning document. This is **not** the final Just One KISS-specific marketing style guide or finished platform specification guide.

**Timeline classification:** `GEN` / GENERAL / NOT TIMELINE-SPECIFIC. Individual campaign assets may later reference a Timeline Moment ID when they promote a precise show moment; otherwise they remain `GEN`.

**Media scope:** Still images only. No video, motion graphics, reels, story animation, trailer cuts, or live footage packages are specified here.

**Primary SSOT sources considered:** `docs/ssot/ads_specs.md`, `docs/brand_story_style_guide_inventory.md`, `docs/ssot/brand_story_style_guide_inventory.json`, `proto/docs/language.json`, `README.md`, `docs/knowledge.md`, `docs/styleguide.md`, `docs/website_system_plan.md`, `docs/owner_admin_build_readiness.md`, `proto/docs/website_ssot.md`, and the active public-site/prototype documentation set.

---

## 1. How to Use This Inventory

Use this document as the starting checklist when deciding what still-image assets to make. It answers:

1. Which platforms and placements may need image creative?
2. Which aspect ratios and dimensions should be planned?
3. Which campaign jobs can be served by still images?
4. Which variants should be made before a launch, reminder, retargeting, or venue-buyer push?
5. Which records should be created in a future owner/admin system for each image asset?

This document intentionally lists possibilities broadly. A later Just One KISS-specific marketing style/spec guide should choose the approved subset, final templates, copy lockups, visual treatments, export rules, and review workflow.

---

## 2. Non-Negotiable Project Guardrails

Every still-image marketing asset should preserve these repository-wide rules:

- Keep public materials original, fan-facing, theatrical, rights-aware, safety-aware, and independent-tribute framed.
- Do not imply official KISS, Gene Simmons, venue, sponsor, ticketing, or outside partnership approval unless later cleared in a public SSOT source.
- Do not use unapproved official logos, exact protected makeup, album art, official memorabilia, restricted fonts, or proprietary staging as generated-image prompts or finished public creative.
- Keep internal cue timing, owner workflows, launch blockers, review-state labels, and show-control internals out of public-facing images unless an approved public document explicitly calls for them.
- Keep verified facts readable as real text whenever they are mission-critical: event name, date, free admission, venue, address, safety note, camping distinction, update-list CTA, and independent-tribute disclaimer.
- Use the public language SSOT (`proto/docs/language.json`) for copy patterns instead of inventing parallel public prose.
- Classify every resulting image record as either a Timeline Moment ID or `GEN`.

## 9. Still-Image Asset Record Fields

Every created image should become a catalogued asset record. At minimum, track:

| Field | Requirement |
| --- | --- |
| Asset ID | Unique stable ID, e.g. `MKT-IMG-GEN-001`. |
| Title/name | Human-readable asset name. |
| Timeline classification | Timeline Moment ID or `GEN`. |
| Campaign job | Announcement, reminder, directions, safety, booking, etc. |
| Platform/placement | Facebook feed, Instagram story, Google display, print poster, website OG, etc. |
| Dimensions/aspect ratio | Pixel size or print size and ratio. |
| File type | JPG, PNG, WebP, PDF, print export, etc. |
| Source copy token(s) | `proto/docs/language.json` tokens or approved document path. |
| Source image/asset(s) | Approved generated image, photo, texture, icon, or design source. |
| Public/private flag | Public, internal, venue-only, draft, or restricted. |
| Rights status | Needs review, approved, rejected, restricted, or replace. |
| Safety status | Needs review, approved, warning required, venue-dependent. |
| Fact status | Verified, pending owner review, outdated, superseded. |
| CTA/destination | Update-list URL, directions URL, contact route, QR target, etc. |
| Owner/responsible role | Performer, public site owner, marketing, designer, venue contact, etc. |
| Review notes | What changed, what needs approval, what cannot be used. |
| Export location | Repository path or asset storage location. |
| Last updated | Date of last content/design/spec update. |

## 11. Review Gates Before Any Image Goes Public

1. **Fact review:** Date, venue, address, admission, camping, parking, CTA, and contact details match current SSOT.
2. **Rights review:** No unapproved official logos, exact protected makeup, album art, official media, or implied affiliation.
3. **Safety review:** Hazards are not hidden where a conversion or attendance decision is being requested.
4. **Public-copy review:** Language matches approved tokens/patterns and does not expose internal mechanics.
5. **Accessibility/readability review:** Critical text remains readable at mobile and print distance.
6. **Platform spec review:** Export dimensions, file type, file size, crop safe zones, and text density fit the target placement.
7. **Timeline/GEN review:** Asset record carries a Timeline Moment ID or `GEN`.
8. **Destination review:** URLs, QR codes, phone numbers, social handles, and update-list destinations are tested.
