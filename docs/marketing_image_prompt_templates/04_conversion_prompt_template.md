A mock form or button is a visual representation unless the asset is embedded in an interactive interface. Do not make a static ad appear deceptively interactive.

## 5. Composition notes

- Use one primary CTA and no more than `[one, two, custom]` secondary actions.
- Keep the offer, material price/admission fact, and CTA within the first visual scan.
- Place applicable terms, eligibility, availability, safety, or consent context near the action.
- For small placements, remove mock field details and retain only the offer, brand/project identifier, one material fact, and CTA.
- If using scarcity or a deadline, display it only when verified and current.
- If using a QR code in print, generate and test the final code outside the image-generation process.
- Use approved screenshots only; remove private data and ensure depicted interface states are current.

## 7. Guardrails and verification

- Verify price, currency, taxes/fees, inventory/capacity, deadline, eligibility, delivery, shipping, cancellation/refund, renewal, trial, subscription, donation, and contact terms as applicable.
- Do not fabricate urgency, countdowns, low-stock claims, limited capacity, endorsements, reviews, savings, crossed-out prices, or guarantees.
- Ensure consent and privacy language matches the actual form and jurisdiction.
- Do not preselect consent in a depicted form unless legally appropriate and representative of the real experience.
- Avoid deceptive button, notification, system-alert, or fake-interface treatments.
- Include relevant safety, age, accessibility, financial, medical, legal, or regulated-product warnings using approved language.
- Reconfirm destination URL, tracking parameters, QR code, platform rules, and dimensions before launch.
