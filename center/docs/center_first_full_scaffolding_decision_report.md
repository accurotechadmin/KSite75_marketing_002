# Center First Full Scaffolding Decision Report

This pass prioritizes owner usefulness, governance before publishing, provenance before editing, Timeline/GEN classification everywhere, scaffold before persistence, serious private software over decoration, adapter-ready contracts, and reference-not-fork behavior.

## Module choices

- Priority Board: gives the owner an action-first surface for notes, questions, now/next/later work, finished items, and recovery before all modules are feature-complete.
- Decision Log: preserves unresolved questions, options, chosen direction, reversal cost, sources, and follow-up record links.
- Release Gates: centralizes rights, safety, privacy, venue, accessibility, copy, media, technical disclosure, and brand-affiliation approvals for public or show-ready outputs.
- Provenance Ledger: distinguishes canonical sources, derived copies, prototype-only seeds, generated outputs, deprecated references, and sync-review needs before facts are trusted.
- Booking / Contacts: represents venue buyers, press, vendors, follow-ups, inquiry source, buyer packet readiness, and private/public boundaries.
- Rehearsal / Prep: represents practice notes, readiness drills, cue fixes, packing prep, rehearsal next actions, and safety-sensitive private details.
- Existing owner modules: dashboard, settings inventory, SSOT library, records, record detail, timeline registry, cue staging, asset inventory, media intake, rights/safety queue, tasks/launch, website drafts, marketing planner, operator outputs, system map, and integrity checks remain because they cover the command, source, website, marketing, technical, rehearsal, booking, and output surfaces the owner needs.

## Placeholder boundaries

All seeds are placeholder or prototype-only. SSOT JSON remains read-only or draft-overlay-only. Runtime writes, uploads, publish buttons, contact storage, approval stamps, deletion, and generated public output must wait for auth, audit trails, backups, permissions, rollback, and persistence.
